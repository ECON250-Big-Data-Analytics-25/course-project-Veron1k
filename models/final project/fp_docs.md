**Зміна типу даних для customer_zip_code_prefix та seller_zip_code_prefix**
Змінено тип даних з INTEGER на STRING для стовпців customer_zip_code_prefix та seller_zip_code_prefix. 
Це зроблено тому, що ZIP-коди — це не числові значення, з якими можна проводити математичні операції 
чи агрегації. Вони служать лише для ідентифікації локацій, тому правильніше зберігати їх як текстові
значення, щоб уникнути можливих помилок при обробці даних, таких як обрізка провідних нулів.

**Зміна пустих рядків на NULL**
У стовпцях seller_city, seller_state, order_status, payment_type, customer_city, customer_state 
пусті рядки було замінено на NULL. Це важливо для коректної агрегації та підрахунку, оскільки порожні 
рядки можуть бути неправильно оброблені при підрахунку або аналізі. Використання NULL дозволяє чітко 
відрізнити відсутні значення від порожніх значень і забезпечує правильну поведінку функцій агрегації, таких
як COUNT, AVG тощо.

**Заміна пустих рядків на "other" у product_category_name**
У колонці product_category_name пусті рядки було замінено на значення "other". Це дозволяє коректно групувати
продукти без категорії в окрему категорію "інше", що полегшує подальший аналіз та робить дані більш 
зрозумілими.

**Створення нових рядків**
days_taken: Показує кількість днів, які пройшли між моментом покупки товару та його доставкою клієнту.
Це дає змогу виміряти ефективність доставки товарів.

is_shipped: Булевий стовпець, який визначає, чи було замовлення відправлене або доставлене.
Встановлюється як TRUE, якщо товар відправлений або доставлений, і FALSE в інших випадках.

**Використання array_agg для агрегації даних**
array_agg(struct(payment_type, payment_value, payment_installments)) as payment_info: 
Цей вираз об'єднує інформацію про методи оплати, суму платежу та кількість платежів у один агрегований масив
Це дозволяє зберігати всі значення, що стосуються платежів по одному замовленню, у вигляді структури, 
що робить дані більш зручними для подальшого аналізу.

array_agg(struct(oi.product_id, oi.order_item_id, p.product_category_name, oi.price, oi.freight_value)):
Цей вираз аналогічно агрегує дані про товари замовлення, зберігаючи їх у вигляді масиву структур, що 
включає ідентифікатор товару, категорію, ціну і вартість доставки.

**Пояснення щодо партіціонування та кластеризації**

Partition by: Для оптимізації запитів, що базуються на датах, таблиця розбивається на партії за полем 
order_purchase_timestamp. Це дозволяє швидше виконувати запити, що фільтрують або агрегують дані по датах.

Cluster by: Кластеризація здійснюється по customer_id і order_status. Це обрано, оскільки ці поля часто 
використовуються для аналізу, і їх кластеризація дозволяє покращити швидкість запитів, що фільтрують або 
групують дані за цими критеріями.
